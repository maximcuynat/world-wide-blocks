# Politique de sécurité / Security policy

[Français](#français) · [English](#english)

## Français

### Versions suivies

Seule la dernière version publiée (alpha, beta ou release) reçoit des corrections de sécurité. Tant que le mod est en 0.x, une correction peut arriver dans une nouvelle version plutôt que dans un correctif de l'ancienne.

### Signaler une faille

**N'ouvrez pas d'issue publique** pour une faille de sécurité.

Utilisez le signalement privé de GitHub :

1. Onglet **Security** du dépôt.
2. Bouton **Report a vulnerability**.
3. Décrivez la faille : version du mod, de Minecraft et de NeoForge, étapes pour la reproduire, effet observé (plantage du serveur, action interdite à un joueur, données lues ou modifiées…).

Le signalement n'est visible que par le mainteneur. Il n'y a pas d'adresse e-mail de contact : passez uniquement par ce formulaire.

### Ce qui nous intéresse

Le serveur décide de tout et le client ne fait qu'afficher. Sont des failles, par exemple :

- un client modifié qui fait planter ou ralentir fortement un serveur (paquet réseau, câble, appareil) ;
- un joueur qui agit sur des appareils, des câbles ou des données hors de sa portée ;
- une sauvegarde de monde qu'un tiers peut corrompre.

### Suite donnée

Le mod est maintenu bénévolement : il n'y a pas de délai garanti. Vous recevrez une réponse dans le fil du signalement ; une fois la correction publiée, la faille pourra être décrite dans un avis de sécurité GitHub, avec votre accord pour vous citer.

## English

### Supported versions

Only the latest published version (alpha, beta or release) receives security fixes. While the mod is 0.x, a fix may ship in a new version rather than as a patch of the old one.

### Reporting a vulnerability

**Do not open a public issue** for a security vulnerability.

Use GitHub's private reporting:

1. Open the repository's **Security** tab.
2. Click **Report a vulnerability**.
3. Describe the issue: mod, Minecraft and NeoForge versions, steps to reproduce, observed effect (server crash, forbidden player action, data read or changed…).

The report is only visible to the maintainer. There is no contact e-mail address: please use this form only.

### In scope

The server decides everything and the client only displays. Examples of vulnerabilities:

- a modified client that crashes or heavily slows down a server (network packet, cable, device);
- a player acting on devices, cables or data out of their reach;
- a world save that a third party can corrupt.

### What happens next

The mod is maintained on a volunteer basis: there is no guaranteed response time. You will get an answer in the report thread; once the fix is released, the issue may be described in a GitHub security advisory, crediting you if you agree.
